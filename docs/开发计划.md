# dsh-study-tree 开发计划

**目标**　在 DSH 内完成一次能跨重启恢复的学习过程：建树、划词、递归追问、返回原句、切换到兄弟分支。

**架构与技术栈**　独立 Cordis bundle，TypeScript、宿主 React、React Flow 自定义问答卡片、Dagre 初始布局、Markdown 渲染器。DSH 管理会话与模型，插件 Host 维护学习树，客户端负责画布与路径阅读。

**设计依据**　[产品与交互设计](设计文档.md) · [本地 DSH 源码核对](DSH插件接入.md)。下列勾选代表已经验证的整项，剩余项可能已有部分实现。文件名为设计阶段建议的位置。

**全程约束与复查重点**　一节点一轮；以父节点和真实会话事件边界确定来源；输入靠近来源卡片；右栏仅显示选中路径；深浅主题都可读。每阶段用真实 DSH 验证该阶段新增的行为，记录宿主版本和复现步骤。

## 1. 先在 DSH 打开学习树

- [x] 创建 `package.json`、`cordis.patch.yml`、`src/host/index.ts`、`src/client/index.tsx`，补齐构建入口、图标和中英文名称。按官方样例生成 Host 和浏览器产物，验证实际包内含全部运行资源。
- [ ] 在 `sidebar.panellist` 和 `main` 注册页面。在测试 profile 中通过「添加插件」选择本地目录，用一个含中文 Markdown 的 React Flow 节点检查 React 共享、依赖打包、样式加载及焦点行为。
- [ ] 在同一 profile 中切换页面、重启和禁用。验收为入口可打开、重启后仍可打开、禁用后入口消失；记录 Web 或桌面哪一端已实际验证。

## 2. 验证真实问答和精确分叉

- [ ] 在 `src/client/session.ts` 接入创建、引用/释放、提交、流式显示及分页。验证已完成轮次能稳定对应其结束事件序号；如公共快照不足，在 `src/host/turn-projection.ts` 补充投影。
- [x] 在根回答后先产生后续内容，再从根的结束位置分别问 A、B，从 A 问 A1。检查实际 fork 会话所继承的事件前缀，比较会话与树中的映射。验收为 B 的历史含根问答，A 与 A1 的问题及回答均不在其中；一轮多次工具调用仍只形成一个问答节点。
- [x] 记录连续追问十轮及从早期轮次多次分叉的延迟、会话数量、日志体积。若需要复用叶端会话，先证明会话尾部仍等于所选边界、没有外部新增轮或待处理输入，并验收并发追问的隔离，再启用优化。

## 3. 让学习树能够恢复

- [ ] 在 `src/shared/tree.ts` 定义节点、父子边、引用和提交状态。在 `src/host/tree-store.ts` 以版本化 domain 保存每棵树；同树修改串行处理并核对版本，新增节点校验同树、父节点存在、无环。通过插件 Host 接口对客户端提供创建树、读取树、记录分支和订阅更新。
- [ ] 将创建分支、获得目标会话、提交问题、确认持久化拆为可辨认的阶段。用稳定操作 ID 合并双击，重连后核对已知会话和宿主返回的错误详情；识别已创建会话但工作区绑定失败的情况。遇到不确定的提交结果，界面保留可恢复的草稿和状态。
- [ ] 用小型用例覆盖两兄弟同轮号、fork 继承历史去重、掉线后重复点击、两个窗口并发新增。重启 Host 后恢复同一树，再与原会话核对每轮问答。缺失来源会话只影响对应节点。

## 4. 完成学习时使用的画布和路径阅读

- [ ] `src/client/StudyPage.tsx` 通过宿主原生侧栏展示目录，在主区域组合中央画布和可伸缩阅读区。`src/client/canvas/TurnCard.tsx` 实现 Markdown、长文折叠和卡下输入。`src/client/reader/PathReader.tsx` 按父链渲染独立的左右气泡，支持定位卡片。三个界面共用一个当前节点 ID。
- [ ] `src/client/canvas/SelectionComposer.tsx` 保存划词来源、显示右键胶囊输入框、支持默认解释和自定义提问。在画布和阅读区分别从同一原句追问；离开选区后仍可正确发送引用。返回时恢复位置，临时突出原句。
- [ ] 实现按节点恢复草稿，键盘发送/取消，触控板缩放，卡头拖动与正文选区互不干扰。拖动、隐藏、重开右栏时保留上次宽度；从子分支返回时恢复到原有内容。
- [ ] 用首版已认可的中性灰阶、圆角卡片、选区胶囊与聊天气泡核对深浅主题。用相同术语出现两次、跨行选区、中文输入法、宽表格、长代码和公式逐一验证。流式输出或展开长文时，正在读的卡片和其他分支位置保持稳定。

## 5. 交付学习笔记与首版验收

- [ ] 在 `src/shared/export-markdown.ts` 复用路径和子树遍历，实现当前路径与整树导出。比较界面和导出顺序，确认代码围栏、引用和中文正文完整。支持改写或重新生成后保留原节点及其后代。
- [x] 在真实 DSH 中走完「学习路线 → 工具调用 → JSON Schema → 返回工具调用原句 → 回根另开上下文管理」。右栏最后恰有两轮，Markdown 导出与这两轮一致。关闭、重启后再返回同一句。
- [ ] 分别检查桌面与 Web、窄窗口、深浅主题及大树缩放。记录尚未覆盖的平台或阻塞项。正式分发前在干净 profile 用分发产物安装一次，确认不依赖开发机的同级 DSH 源码目录。

## 开发分支验证记录（2026-11-16）

在独立配置中安装了本地分发包，并用 DSH 0.2.2-rc.3 Web 和 Edge 验证。问答、流式事件、历史分叉及存储均走宿主接口，模型端使用本机测试服务返回固定文本。已检查侧栏入口、两级划词、返回原句高亮、兄弟分支的实际模型请求、右栏宽度恢复、导出路径、重载后的选中路径和重命名。十轮连续问答的这次测试耗时约 4.6 秒，产生 10 个会话，压缩日志合计 365875 字节。这组数值来自短文本模拟回答。

桌面窗口、真实模型的延迟与长回答、超大树、断网期间的人工恢复以及完整禁用流程仍需独立验收。当前 Host 服务通过 DSH Gateway 读写 storage domain。页面打开、窗口重新获得焦点和宿主重连时刷新目录，跨窗口实时推送尚待实现。
最终分发包在另一套全新的 DSH 配置中完成安装，并重复通过两级划词、兄弟分支、原句高亮、导出及页面刷新验证。重启该宿主后，4 个测试节点及其 4 份回答均能从持久化数据中恢复。

0.1.1 在同一 DSH Web 测试配置中对比了含 42 个小节的长回答。连续输入 20 个字符时，草稿存储写入从 20 次降至 1 次。另已验证原生侧栏目录、切树恢复草稿、卡片拖动、阅读区伸缩与收起、长文展开及划词后返回原句。
