## 0.3.1 鼠标拖动性能修复

旧实现每次鼠标移动都把只含位置的节点对象回传 React Flow。对象缺少此前测量的尺寸，React Flow 会清除连接点边界并重新测量，连线在拖动期间反复被移除、重建，触发页面排版和重绘。更新为 React Flow 的节点状态及变更处理，保留测量结果，外部回答和布局更新保留当前拖动位置，松手后持久化坐标。

使用同一独立 DSH 0.2.2-rc.3 Web 配置、Edge、1440×900 窗口和四节点数据，分别记录平移、120 次鼠标移动拖动及滚轮缩放。浏览器 CPU 设为四倍降速以放大差异。拖动帧间隔 95 分位在本次对照中从 50ms 降为 12.4ms。原本在拖动阶段出现的 221 次整页 DOM 观察回调降为 0，连线 SVG 持续复用。该数据来自受控网页测试。

另以 100 次连续鼠标移动检查了连线路径的 DOM 身份，拖动中保持同一节点，坐标在松手后保存。回归验证通过拖动坐标跨重载恢复、自动布局复位、曲线与圆角折线、原生阅读路径、长文展开后的避让以及窄窗口。浏览器成功流程无页面错误。桌面实机帧率尚待单独测量。

## 0.3.2 空白平移的绘制开销

用户进一步澄清：按住空白处拖动，鼠标连续移动，画布会停一下再追上。此症状与上一版修复的节点拖动尺寸丢失不同。坐标采样中的五次平移、896次视口变化均与鼠标位移一致，没有重挂载、容器尺寸变化或坐标回弹；这只排除了该受控场景中的位置回写问题，不代表用户前台已无停顿。

确认了一条持续开销：React Flow 的 Background 订阅完整视口，每次平移通过 React 更新 SVG pattern 的 x/y，重绘整片背景。改用订阅同一 React Flow store 的独立点阵纹理；平移只同步写 transform，缩放才改变点距与点大小。纹理使用有界取模和四边一格的覆盖量，保留 DSH 主题色、24px点距和1px点大小。视口增加合成提示；拖拽、滚轮和节点状态仍由 React Flow 处理。

对照使用隔离 DSH 0.2.2-rc.3 Web 配置、四节点数据以及从当前安装提取的 Electron 44.7.0 / Chromium 152运行时；独立数据目录、隐藏的离屏窗口、Intel D3D11硬件合成，1920×1080、设备倍率2和CPU四倍降速。每段约3秒，按125Hz注入360次鼠标移动，浏览器合并后处理约240次。两轮候选对照中 Paint 为471/465次，改为独立纹理后均为0；最终0.3.2产物再次对照为492次降至0次，FunctionCall总耗时743ms降至440ms。它证明这条持续重绘路径已消除，并减少脚本工作量。

这些数据不等于前台桌面操作已全部解决：普通RAF的95分位前后均约16.7ms，输入延迟没有稳定改善。测试另捕捉到一次约63ms的MajorGC暂停，不能据此认定用户的停顿都由内存回收造成，也不能证明它由背景单独引起。此前测试轨迹曾进入原生左侧栏，触发滚动条显示与隐藏；本轮起点验证为空白pane，轨迹保持在画布内。关闭右侧阅读区的对照未显示改善。用户真实前台操作仍需要复测。
