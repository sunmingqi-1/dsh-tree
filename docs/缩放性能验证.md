# 0.6.1 连续缩放性能验证

日期：2026-11-17。用户确认 0.6.0 的文字清晰度符合预期，但连续滚轮缩放有低帧率感。本次定位并降低了持续缩放的绘制开销，尚未在用户真实桌面测量最终帧率。

## 原因与修改

0.6.0 为避免文字沿用旧比例的缓存，在滚轮或程序缩放期间持续使用 `will-change: auto`。它允许浏览器在每个中间缩放比例重新绘制，长篇 Markdown、遮罩等会参与绘制。单独保持 `transform` 合成提示的对照中，RasterTask 与 Paint 的累计耗时明显降低，表明此路径是已确认的额外开销。

0.6.1 仅在手势期间复用绘制层，缩放结束后切为 `auto`，允许浏览器按最终比例重新绘制文字。保留真实 Markdown 和原生输入组件，不通过隐藏正文、删除遮罩、改节点尺寸或自动布局来减少工作量。连线、缩放坐标及手势仍由 React Flow 处理。

策略依据：[Chrome 关于脚本缩放与重绘的说明](https://developer.chrome.com/blog/re-rastering-composite)。缩放过程中可能短暂使用较低比例的文字缓存；停下后不再固定缓存比例。

## 对照方法

使用独立 DSH 0.2.2-rc.3 Web 配置、Edge 无头模式、1600 × 1000 窗口、设备倍率 2、CPU 四倍降速。树中有两张长文卡片，每张正文 42 个小节，选中卡片包含实际原生输入框，右侧原生对话可见。

每段通过 CDP 注入 180 次滚轮输入，间隔约 16ms，反复放大/缩小约 2.9 秒，随后等待 200ms。使用相同页面、内容和新版标题栏，顺序为候选、原策略、原策略重复、候选重复。原策略通过单一 CSS 覆盖强制视口 `will-change: auto`，候选使用实际插件的手势策略。DevTools Trace 记录渲染任务；测试后解除 CPU 降速并关闭隔离浏览器。

两轮 Paint 合计由 1427.342ms 降至 716.684ms，减少约 50%；RasterTask 合计由 215.134ms 降至 19.326ms，减少约 91%。两组实际视口更新数相近，候选并未通过丢弃大量视口更新来取得结果。样本成功流程没有页面错误。

RAF 间隔与后台合成调度受到无头模式、机器负载和采样开销影响，不能换算成用户桌面的最终显示帧率。本结果证明减少了特定绘制路径的工作量，不代表全部掉帧原因已消除。

## 回归

先以新行为编写测试，旧实现中连续滚轮和捏合两项失败，再修改绘制策略，31 项测试通过。实际浏览器滚轮放大/缩小期间视口保持合成提示，停下后为 `auto`；按钮缩放也恢复该状态。正文与输入编辑器保持相同 DOM，节点坐标、手动尺寸及原生草稿保留。另回归悬浮遮罩无外沿漏字、末尾可读、原生独立草稿切换及重载、划词高亮、圆角菜单、深浅主题和 440px 窗口。

标题栏直接使用原生输入框颜色。深色模式下实测标题与输入框均为 `rgb(44, 44, 46)`，卡片正文背景为 `rgb(21, 21, 23)`；恢复尺寸按钮已移除。本轮不修改用户 GPU 配置、不自动重启用户 DSH。

## 0.6.2 标题层补充验证

用户确认 0.6.1 停止缩放后一两秒标题仍然模糊。隔离 Edge 和独立 Electron 44.7.0 / Chromium 152 中，视口结束时的 `will-change` 均已为 `auto`，不能把问题简单归因于结束回调完全没有执行。局部轮廓、取消标题内部滚动等探针未改变同一尺度截图；未稳定复现用户截图中的同等模糊程度，不能据此定位所有桌面成因。

0.6.2 改为标题在初始化和缩放结束时独立按显示字号排版。使用局部 CSS zoom 与反向 transform 使最终合成倍率为 1，并保留原位置和宽度。只写标题元素的局部变量，不更新祖先共享变量，不逐帧重排标题或 Markdown。正文继续使用 0.6.1 策略。问题标题采用 DSH 主文字色。

先新增测试，旧实现因未通知标题更新而失败，修改后 32 项测试通过。在倍率 1.5 的 Edge 与隔离 Electron 离屏窗口中，验证缩放停止后标题 CSS zoom 等于画布比例，标题反向矩阵与画布矩阵相乘约为 1；Electron 覆盖 28%、100%、165% 及滚轮的非整比例。标题的世界坐标左上偏移保持 13px / 11px（包含卡片边框），宽度误差低于 0.15px，卡片世界尺寸不变。标题高度有少量字体与边框取整差异，由原测量器更新正文遮罩。

真实连续滚轮操作的中途标题局部变量更新数为 0，结束后为 1。标题和输入 DOM 保留、草稿不丢失；刷新后按已保存比例初始化，放大后的标题拖动仍能移动节点。深浅主题、悬浮边缘像素检查、正文末尾、原生草稿恢复、划词高亮、圆角菜单和 440px 窗口回归通过。没有重新宣称 0.6.1 的耗时数据代表本版实机帧率；用户当前前台的清晰度与流畅度仍需确认。
