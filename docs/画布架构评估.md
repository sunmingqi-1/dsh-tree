# 拖动连续性与画布引擎评估

日期：2026-11-16。依据：用户提供的7.7秒录屏 `20261116_230502.mp4`、当前插件源码，以及候选项目官方源码和文档。

## 当前结论

录屏中少量问答节点仍有明显的停留后整体移动。0.3.2减少背景重绘没有解决用户的实际体验，不能用Paint次数减少作为拖动连续性已经通过的证据。录屏没有JavaScript调用栈，尚不能把停顿归因于React、React Flow或者DSH中的某一处更新。

React是界面组件技术，React Flow是当前节点画布引擎。替换画布引擎不必重写DSH插件、分支数据和原生对话集成。应先通过同内容、同宿主的原型对照决定是否替换。

## basketikun/infinite-canvas

已浅克隆到临时参考目录，只读源码；没有安装依赖或运行其代码。检查提交：`9cd3deacbcc598361807afc16c059a80dd18b6f9`。

- 它是完整AI创作应用，并非可直接替换React Flow的画布SDK。
- `web/package.json`使用React 19.2.5。换成它并不是离开React。
- `web/src/components/canvas/infinite-canvas.tsx`自行处理Pointer事件，用requestAnimationFrame合并平移更新，通过CSS translate/scale移动HTML内容。
- 页面层仍用React状态保存视口。因此，不能单从源码推断它比React Flow更流畅。
- 可参考其交互和视口更新节奏；提取实现仍需维护节点拖动、连线、选区、自动布局、输入焦点及缩放坐标等功能。

来源：[项目](https://github.com/basketikun/infinite-canvas)、[依赖](https://github.com/basketikun/infinite-canvas/blob/main/web/package.json)、[画布实现](https://github.com/basketikun/infinite-canvas/blob/main/web/src/components/canvas/infinite-canvas.tsx)。

## 候选适配性

以下为架构适配分析，尚未进行候选引擎的同场景性能对照，不是性能排名。

| 方案 | 与学习树需求的关系 | 决策 |
| --- | --- | --- |
| React Flow | 现有Markdown、划词、卡片输入、连线及布局均已接入 | 保留为基线，先做脱离宿主的最小复现 |
| AntV X6 | HTML/SVG图编辑引擎，支持HTML与React自定义节点，采用MVC模型 | 若替换引擎，优先做同场景对照原型；不能保证解决共享主线程的阻塞 |
| 提取infinite-canvas交互层 | React加自行管理的HTML视口；需要维护完整交互基础设施 | 参考实现，不整体迁入AI创作应用 |
| PixiJS | 可用纹理绘制富文本，但其HTMLText会将HTML栅格化 | 全面纹理化不利于当前核心的浏览器文字选区、复制和输入；若采用需额外HTML交互层，暂非首选 |

来源：[React Flow性能说明](https://reactflow.dev/learn/advanced-use/performance)、[X6官方项目](https://github.com/antvis/X6)、[PixiJS HTMLText](https://pixijs.com/8.x/guides/components/scene-objects/text/html)。PixiJS方案的交互成本属于基于其栅格化机制与本项目需求的工程判断。

## 下一步验证顺序

1. 使用相同的少量节点和真实长度Markdown，做独立React Flow最小画布，再与DSH内同内容画布对照。区分画布本身与宿主集成路径。
2. 若最小画布流畅、DSH内停顿，定位宿主共享线程上的长任务、更新范围与布局失效。替换引擎仍可能保留这些阻塞。
3. 若最小画布也不能达到要求，或者集成方式需要隔离，再建立X6原型，与现有实现放入相同DSH环境测试。沿用同一分支数据与Markdown组件。
4. 以真实前台鼠标连续拖动的显示连续性和输入到显示延迟验收；测量长任务并定位来源。帧间隔、Paint次数只作辅助指标。
5. 确认收益后才迁移正式画布，保留数据、引用及原生阅读路径。当前没有实施架构迁移。
