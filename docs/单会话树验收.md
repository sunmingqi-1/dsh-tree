# 单会话学习树验收

使用本分支和配套的 DeepSeek Harness `feat/single-session-tree` 构建。原版 0.2.2-rc.5 的输入组件会提示升级宿主。旧版 fork 学习树仍可阅读，首次使用新结构时新建学习主题。

在插件仓库运行 `npm ci`、`npm test` 和 `npm run build`。单元测试包含清空插件索引后从宿主日志重建、空闲压缩后的父边界，以及异步问询续轮与原卡片的对应关系。

## 浏览器与磁盘

在独立的 `DSH_HOME` 创建 Web 测试 profile，使用 `@deepseek-ai/dsh-base`、`@deepseek-ai/dsh-web-app` 和当前插件三个 bundles。将该 profile 的 `dsh-study-tree` 依赖指向独立构建目录。启动本地 mock 和配套宿主时使用同一个测试环境，例如在 PowerShell 中设置以下变量。

```powershell
$env:STUDY_MOCK_API_KEY = 'local-test'
$env:DSH_QA_OUTPUT = Join-Path $env:TEMP 'study-tree-mock'
$env:DSH_QA_LOG = Join-Path $env:TEMP 'study-tree-web.log'
$env:DSH_QA_SESSIONS = Join-Path $env:DSH_HOME 'sessions'
```

启动 `node scripts/qa/mock-model.cjs`。默认监听本机 54382 端口，对应 `scripts/qa/model.patch.yml`。在另一个终端用配套宿主和该 patch 启动测试 profile，将宿主输出写入 `DSH_QA_LOG`，然后运行下列命令。浏览器默认使用本机 Edge，`DSH_QA_BROWSER` 可指向其他 Chromium 可执行文件。

```powershell
node scripts/qa/session-paths.cjs
node scripts/qa/selection-navigation.cjs
node scripts/qa/native-questions.cjs
node scripts/qa/native-approvals.cjs
node scripts/qa/native-reload.cjs
```

路径用例先发送 A，从卡片继续 B，返回 A 从右栏发送 C，再从 B 发送 D。首轮至末轮的 Session ID 相同，磁盘始终只增加一个 session 日志。模型请求记录中，C 继承 A，D 继承 A、B。右栏选中 D 时显示 A、B、D。其余用例分别覆盖选区草稿、会话中的问题确认、审批，以及流式回答期间刷新恢复。
