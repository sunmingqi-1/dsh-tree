# 学习树 · 产品与交互设计

**项目名为 `dsh-study-tree`，在 DSH 中显示为「学习树」。** 名字对应用户保存和重新打开的东西：围绕一个主题，通过追问长成的一棵树。每个节点恰好对应用户的一问和 Agent 的一轮回答。

当前开发版本为 0.3.2。本轮改版以 DSH 原生工作区、原生起始页和完整原生会话界面为基础，新增画布及节点导航。实现与实际验证范围见[开发计划](开发计划.md)。

## 用一次学习过程验收设计

根节点问「学习 DSH 从哪里开始？」。读到回答里的「工具调用」，选中这四个字，追问「举一个实际例子」。新回答又提到「JSON Schema」，从这里再问「为什么要描述参数类型？」。读完后点「返回原文」，应先回到「JSON Schema」出现的那句话，再返回上层的「工具调用」。这时仍能在根节点另开「上下文管理」，右栏只显示根节点与这条新问答。第二天打开同一棵树，还能定位此前读过的原句。

## 三栏与输入

| 区域 | 内容与操作 |
| --- | --- |
| DSH 原生工作区区域 | 在已有工作区内，学习主题作为可展开项，其后代按问答节点的父子关系缩进、折叠。一项对应一个画布节点，标题使用该轮的问题。点击主题或追问，在主区域打开对应画布并选中节点；恢复该树的画布视角和阅读位置。 |
| 中央无限画布 | 一个节点一轮问答，正文渲染 Markdown。沿上到下的方向按父子关系连线，同级分支左右并列。选中节点时突出从根到它的路径。拖动空白平移，通过卡头移动卡片，正文可正常划词、复制、滚动。远处看问题标题，拉近后读问答。 |
| 右侧原生对话阅读区 | 沿用 DSH 自己挂载的完整会话界面，包括会话标题、模式和当前安装提供的对话、统计等页签，以只读方式呈现从根节点到当前选中节点本轮结束的内容，保留宿主已有的消息、代码和工具调用详情展示。采用原生消息布局；点击「定位节点」回到对应卡片。阅读区与画布同时显示，左边界可拖动调宽，也可收起，重开时恢复宽度与同一路径的阅读位置。 |

新建主题使用 DSH 原生起始页。点击「以学习画布开始」后，在原生输入框中选择模型、模式与工作区并发送首个问题，该轮问答自动记录为根节点，画布随即显示在原生会话左侧。

后续点击节点，在该卡下方展开一个输入框。采用已确认的 Codex 式圆角输入区，正文在上，操作和发送按钮在下；Enter 发送，Shift+Enter 换行，中文输入法确认候选词时不发送。按节点保存草稿。

首轮之后，右侧会话保留宿主原有框架并收起原生输入区，提交追问的入口位于节点卡片及划词胶囊内。左侧列表项、画布节点和右侧路径共用当前节点 ID，任一处定位或切换后同步另外两处。原生对话组件内的正文选择、复制、滚动和详情展开继续可用。

在卡片或阅读区的 Agent 正文中划词，右键打开并聚焦选区旁的单行胶囊输入框。输入可选问题后发送；留空发送采用「请解释『选中文字』」。Esc 取消。引用属于实际被选中的回答，即使读者正从更深的节点浏览祖先消息。成功后选中新子节点，来源卡的原有草稿保留。

## 工作区中的层级列表

侧栏沿用 DSH 工作区区域，移除独立的「学习树」导航项和账户菜单上方的「学习目录」。工作区内可同时出现普通会话与学习主题。学习主题自身就是根问答，展开后显示它的子节点；继续展开子节点可浏览更深的追问。

```text
工作区
  ▾ 学习 DSH
      ▾ 请介绍整体架构
          ▾ 工具调用如何实现？
              JSON Schema 是什么？
          上下文如何管理？
      如何开发插件？
  其他普通会话
```

层级与画布的父子边一致。展开、折叠只改变目录的可见性；切换主题时保存各自的展开状态。选择深层节点时显示其祖先，侧栏选中项与画布路径同步。主题内按创建顺序排列同级节点，保持分支位置稳定；普通会话沿用宿主原有排序。

插件依据持久化的节点与会话映射聚合学习会话，使每个学习节点在所在工作区内只出现一次。现有学习树与会话继续使用原 ID。目录迁移时从根会话的实际工作区恢复归属，子节点随主题归组；无工作区的主题显示在「未分组」中。列表按每个节点自己的问题命名，避免分叉继承的会话标题造成混淆。普通会话保留宿主原有的打开方式。

DSH 当前的工作区树按已登记目录的路径组织，会话行本身仍为平铺。实现本设计需要扩展工作区会话列表的渲染和导航，再复用现有工作区数据及行操作。具体扩展方式须在本地宿主中验证，接入依据见 [DSH 插件接入](DSH插件接入.md)。

## 回到原句与长文阅读

- 子节点保留引用摘录和「返回原文」。定位来源时恢复来源卡的展开状态与阅读位置，必要时展开文本，再短暂高亮原句。同一短语出现两次时按消息标识、文本块、偏移及前后文区分；无法唯一定位时展示原摘录并定位到来源消息。
- 卡片默认折叠长回答；右侧使用原生组件连续阅读完整内容。代码块和宽表格在自身区域横向滚动，卡片中的 Markdown 排版与宿主正文保持视觉一致。划词和返回定位使用统一的可见文本规范。正文保留可复制代码和可选择文本，卡片渲染禁用原始 HTML。
- 画布、卡片、文字、边框和输入区读取 DSH 默认主题变量，随宿主明暗主题变化。保留约 18px 卡片圆角和细连线。选中态同时有轮廓和路径线。输入区、流式增长、折叠和阅读栏拖动均保持当前阅读锚点；Dagre 用于初次布局和显式整理，后续插入优先使用邻近空位。小窗口先收起目录和阅读区，保留画布及重新打开入口。

## 纵向布局与连线

父节点从卡片底部连接子节点顶部，树沿上到下的方向延伸。画布底部工具栏提供两种连线方式，默认使用曲线。圆角折线沿水平与垂直方向连接，转角采用 12px 圆弧。连线方式作为当前设备的偏好保存，切换后即时作用于当前画布。

「自动布局」按卡片实际宽高安排节点，同一层的问题标题顶端对齐，父子之间保留间距，并将整棵树适配到画布视野。操作只重新排列当前学习树，当前选中节点、问答及原生对话路径继续保留。

初次迁移已有横向画布时，重新计算纵向坐标并记录该树的布局版本。之后新增节点优先放在父节点下方，遇到已有卡片时在同一行向右避让，保留原有卡片的位置。展开长文或出现输入区使卡片变高时，下方冲突节点向下让位，列坐标保持。收起内容后保留间距，可点击「自动布局」重新收紧。

## 节点、会话与学习笔记

| 记录 | 需要的数据 |
| --- | --- |
| 学习树 | 稳定 ID、标题、工作区、根节点 ID、版本 |
| 问答节点 | 稳定 ID、树 ID、父节点 ID、继续或引用关系、DSH 会话 ID、本轮起止事件序号、状态 |
| 引用锚点 | 来源节点、源消息标识、文本块与可见文本偏移、选区原文、前后文；以同一文本规范提取和匹配 |
| 阅读状态 | 每棵树的选择、坐标、缩放、展开状态；每节点草稿、返回原文位置，阅读区宽度及可见性 |

DSH 会话日志保存问答正文；插件 Host 保存树结构、引用和请求关联，客户端保存设备上的阅读偏好。节点身份独立于宿主轮号，兄弟分支完全可能拥有相同轮号。右栏的可见轮次与 Markdown 导出共用同一条路径计算。整树导出按分支嵌套输出，每节点包含自己的问答与来源摘录。

首版以**精确边界优先**。根问答通过原生新会话完成并记录来源请求。每个后续节点，无论从卡片继续还是从选区追问，均从父轮已完成的结束序号 fork，随后提交本次问题与可选引用。这样普通追问和历史节点追问使用同一规则，递归分支只继承祖先历史，DSH 仍负责系统提示、工具及上下文压缩。每次追问会增加一个宿主会话并复制历史，成本验证见[开发计划](开发计划.md)。生成期间可以先写追问草稿，待父轮具有可用边界再发送。

原生阅读区的输入数据按插件记录的祖先链和结束序号确定。已完成节点展示截止该轮结束的内容，生成中的当前节点随本轮事件更新；宿主会话后来追加的内容保持在对应节点边界之外。继承历史只展示一次。工具调用、返回结果及消息详情需能关联到各自所属的问答节点，从祖先正文划词时仍能正确确定引用来源。

历史问题的改写或重新生成作为同一来源下的新版本保留，原有回答和后代仍可访问。改写根问题时新建同主题的树并链接来源，以保持每棵树只有一个根。重新答复、导出和大树性能优化安排在基本学习流程通过后。

## 中断与恢复

提交、生成中、完成、停止和失败分别呈现。先落盘操作 ID、来源和草稿，再记录 fork 返回的目标会话 ID，最后用已持久化的用户消息和结束记录对账。已知目标会话时继续使用该会话；提交结果未知时先核对宿主历史。若创建结果丢失且无从可靠识别，保留草稿、告知状态未知，由用户决定是否重新发起。来源会话被移除时保留树的位置和已存摘录，清楚标记正文不可用。

插件入口与宿主接口见 [DSH 插件接入依据](DSH插件接入.md)。

右侧原生对话在本次迁移后默认宽度为 480px，可继续拖动调整。画布菜单中的「打开完整对话」恢复原生全宽会话与输入区。
